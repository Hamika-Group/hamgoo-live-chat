# Hamgoo Live Chat

[فارسی](../README.md) · [English](readme-en.md) · [العربية](readme-ar.md) · Русский · [اردو](readme-ur.md)

Подключите WordPress к чату Hamgoo с помощью открытого ключа виджета. Панель в тёмно-синих и голубых цветах управляет страницами показа и временем загрузки. Переписка, операторы, оформление чата и часы работы настраиваются в облачном сервисе Hamkaran.

[Сервис, покупка и консультация](https://hamkaran.cloud/) · [Кабинет и поддержка](https://cp.hamkaran.cloud/) · [Загрузки](https://github.com/Hamika-Group/hamgoo-live-chat/releases) · [Ошибки плагина](https://github.com/Hamika-Group/hamgoo-live-chat/issues)

## Требования и возможности

WordPress **6.5+**, PHP **7.4+**, учётная запись Hamkaran и активный виджет Hamgoo с разрешённым доменом сайта. WooCommerce необязателен. Плагин бесплатный; облачный сервис может требовать платной подписки. На сайте клиента не нужны Composer, Python и Node.js.

- Подключение по ключу виджета; не вводите пароль или закрытый токен API.
- Персидский, английский, арабский, русский и урду; отдельный выбор языка плагина и поддержка RTL.
- Все или выбранные страницы; поиск опубликованных записей/страниц и выбор публичных типов содержимого.
- Главная, список записей, архивы, поиск, 404 и правила WooCommerce.
- Точные пути и wildcard; исключения всегда важнее условий показа.
- Мобильные/настольные устройства; загрузка при простое браузера, с задержкой или по нажатию.
- API согласия, инструкция, ручная проверка конфигурации и рекомендуемый текст политики конфиденциальности.
- Отдельные настройки сайтов сети и необязательная очистка при удалении.

## Установка

1. Скачайте **hamgoo-live-chat-X.Y.Z.zip** из Releases. Автоматические архивы GitHub «Source code» не являются готовым установочным пакетом.
2. В WordPress откройте Плагины → Добавить новый → Загрузить плагин, установите ZIP и активируйте.
3. В кабинете Hamkaran включите Hamgoo, создайте виджет в настройках Hamgoo → Виджет и укажите разрешённые домены.
4. Откройте меню Hamgoo в WordPress, введите только ключ `cw_`, подтвердите подключение к сервису, включите чат и сохраните.
5. Настройте показ и загрузку. Удалите прежние скрипты установки из темы, менеджера тегов или других плагинов.
6. Очистите кеш страниц/CDN. Отправьте сообщение с разрешённой страницы и проверьте получение и ответ оператора.

Ручная проверка запрашивает конфигурацию из браузера администратора. Успех не подтверждает разрешение домена или доставку сообщений.

## Правила показа и WooCommerce

Режим всех страниц допускает подходящие публичные страницы. Для выбранных страниц должно выполняться хотя бы одно условие включения; без условий чат скрыт везде. Условия объединяются через «ИЛИ». **Любое исключение скрывает чат.**

Пути задаются относительно домашнего URL WordPress, по одному в строке. Параметры query не учитываются. `/contact` совпадает с конечной косой чертой и без неё. `/services/*` охватывает дочерние пути; для родительского добавьте отдельный `/services`. `/*` охватывает всё.

При активном WooCommerce можно включать/исключать магазин, товары, архивы товаров, корзину, оформление заказа и кабинет. Для нестандартных страниц используйте выбор страницы или путь. Остальные правила работают без WooCommerce. Загрузчик не вставляется в админку, AJAX, REST, cron, feeds, embeds и предварительный просмотр.

## Загрузка и производительность

Режим простоя ждёт готовности страницы и свободного времени браузера. Задержка отсчитывается после готовности страницы. По нажатию сервис загружается после клика на локальную кнопку и согласия, если оно требуется. Затем появляется настоящий виджет; автоматическое открытие разговора зависит от настроек Hamgoo.

Устройство определяется в браузере для совместимости с кешем страниц; ширина до 767 пикселей считается мобильной. Плагин управляет загрузкой, не меняет SEO-метаданные и не гарантирует позиции поиска или оценки производительности.

## Согласие и внешние сервисы

Включите ожидание согласия и подключите имеющийся менеджер согласия на каждой странице. Плагин не содержит баннера cookies и не сохраняет согласие.

```js
// Согласие до запуска загрузчика:
window.HamgooLiveChatConsent = true;
// Согласие после запуска:
if (window.HamgooLiveChat) window.HamgooLiveChat.grantConsent();
// Отзыв:
window.HamgooLiveChatConsent = false;
if (window.HamgooLiveChat) window.HamgooLiveChat.revokeConsent();
// Для остановки уже работающего виджета перезагрузите страницу без согласия.
// Альтернатива после запуска загрузчика:
window.dispatchEvent(new CustomEvent('hamgoo:consent', {
  detail: { granted: true }
}));
```

Согласие не отменяет исключения страниц или ограничения устройств. Отзыв блокирует будущую загрузку; полная остановка уже работающего внешнего кода требует перезагрузки без согласия.

После выполнения условий загружается `cp.hamkaran.cloud/widget/chat.js`. Виджет также использует `api.hamkaran.cloud`, ресурсы `cp.hamkaran.cloud`, вложения/изображения `storage.s1.hamkaran.cloud`, клиент `js.pusher.com` и настроенный websocket.

Запросы раскрывают IP и обычные данные браузера. Сервис может обрабатывать URL/заголовок страницы, источник перехода, браузер/сеанс и предоставленные посетителем имя, телефон, email, сообщения, статус набора, файлы и аудио. Используются localStorage/sessionStorage; запись голоса требует разрешения микрофона. WordPress хранит только настройки, не облачные разговоры. Открытие панели не вызывает автоматических запросов к сервису.

Подробнее: [внешние сервисы](../readme.txt), [конфиденциальность](https://hamkaran.cloud/privacy-policy/), [соглашение](https://hamkaran.cloud/%D8%AA%D9%88%D8%A7%D9%81%D9%82-%D9%86%D8%A7%D9%85%D9%87-%D8%A7%D9%85%D9%86%DB%8C%D8%AA%DB%8C/).

## Языки, изображения и удаление

Переводы относятся к панели плагина и локальной кнопке. Язык облачного чата, цвета, положение, приветствие и часы настраиваются в Hamgoo. Локальные SVG временные; [инструкция по изображениям на персидском](artwork-fa.md) описывает замену WebP и материалы каталога. Скриншоты должны показывать реальный плагин.

Деактивация сохраняет настройки. Удаление очищает настройки текущего сайта только при включённой очистке; облачные разговоры остаются. Каждый сайт сети имеет собственный ключ и настройки.

## Решение проблем

- Чат отсутствует: проверьте сервис, ключ, подтверждение, домены, условия, исключения, устройство и согласие.
- Старые настройки: очистите кеш страниц/CDN. Тема должна вызывать `wp_head()` и `wp_footer()`.
- Конфликт оптимизации: при необходимости исключите `hamgoo-loader`, `HamgooLiveChatLoader` и `cp.hamkaran.cloud/widget/chat.js` из объединения/дополнительной задержки, сохраняя согласие.
- Проверка не работает: причиной могут быть настройки браузера или CORS; проверьте настоящую переписку.
- Дублирование: удалите прежнюю установку.

Вопросы сервиса направляйте в поддержку кабинета, ошибки кода — в Issues. Не публикуйте пароли, токены, персональные данные и клиентскую переписку.

## Разработка и выпуски

Нужны PHP 7.4+, Composer, Python 3.9+ и Node.js. В корне проекта:

```sh
composer install --no-interaction
composer lint
php tests/run.php
node --check assets/js/admin.js
node --check assets/js/loader.js
node tests/loader.test.js
python3 scripts/translations.py
git diff --exit-code -- languages
python3 scripts/verify.py
php scripts/preview.php
python3 scripts/package.py --tag v1.0.2
```

Источник переводов — `languages/translations.json`. Генерация PO/MO/POT завершается ошибкой при неполных переводах. Статические макеты создаются в `docs/*-preview.html`; реальный поиск и связь требуют WordPress.

Необязательный тест: `wp eval-file tests/wordpress-smoke.php`, **только в отдельной временной установке WordPress** с активным плагином. Создаёт временные записи/настройки; не запускайте на рабочем сайте.

Согласуйте Version и HAMGOO_VERSION главного файла, Stable tag в readme.txt и тег выпуска. Обновите журнал изменений и проверки, сделайте commit:

```sh
git tag v1.0.2
git push origin main
git push origin v1.0.2
```

[CI](../.github/workflows/ci.yml) проверяет код, переводы и пакет. [Release](../.github/workflows/release.yml) публикует ZIP и SHA256SUMS после успешных проверок. Ручной запуск Actions принимает существующий стабильный тег. Повтор обновляет файлы того же выпуска; не перемещайте опубликованный тег. Скачайте оба файла вместе и выполните `sha256sum --check SHA256SUMS`. ZIP не содержит тестов, vendor, документации разработки и workflow.

Аккаунт издателя и идентификатор WordPress.org ещё не подтверждены. Contributors пуст до получения реального имени; обычный CI исключает только это предупреждение, пока поле пусто. Публикация WordPress требует полной проверки. После одобрения настройте имя, изображения и секреты SVN по [инструкции](release-fa.md). [Ручной workflow](../.github/workflows/wordpress.yml) проверяет checksum и публикует в SVN. Обновления через WordPress.org; отдельного обновлятора GitHub нет.

Код и SVG: **GPL-2.0-or-later**, см. [LICENSE](../LICENSE). Новые изображения должны иметь совместимую лицензию. [readme.txt](../readme.txt) содержит стандартное описание каталога.
