# Hamgoo Live Chat | همگو

[فارسی](../README.md) · [English](readme-en.md) · العربية · [Русский](readme-ru.md) · [اردو](readme-ur.md)

اربط موقع ووردبريس بخدمة همگو باستخدام مفتاح الودجت العام. لوحة الإدارة باللونين الكحلي والأزرق تتحكم في صفحات العرض ووقت التحميل. تُدار المحادثات والمشغّلون ومظهر الدردشة وساعات الرد في خدمة همكاران السحابية.

[التعريف والشراء والاستشارة](https://hamkaran.cloud/) · [الحساب والدعم](https://cp.hamkaran.cloud/) · [التنزيل](https://github.com/Hamika-Group/hamgoo-live-chat/releases) · [بلاغات الإضافة](https://github.com/Hamika-Group/hamgoo-live-chat/issues)

## المتطلبات والمزايا

ووردبريس **6.5+** وPHP **7.4+** وحساب همكاران وخدمة همگو وودجت نشطان مع السماح بنطاق الموقع. WooCommerce اختياري. الإضافة مجانية، وقد تتطلب الخدمة السحابية اشتراكًا مدفوعًا. لا يحتاج موقع العميل إلى Composer أو Python أو Node.js.

- اتصال بالمفتاح فقط؛ لا تُدخل كلمة المرور أو رمز API خاصًا.
- الفارسية والإنجليزية والعربية والروسية والأردية، مع اختيار لغة خاص بالإضافة ودعم RTL.
- كل الصفحات أو صفحات مختارة، وبحث في الصفحات والمقالات المنشورة وأنواع المحتوى العامة.
- الرئيسية وفهرس المقالات والأرشيف والبحث و404 وقواعد WooCommerce.
- مسارات دقيقة أو wildcard، واستثناءات تتقدم دائمًا على قواعد العرض.
- الجوال/سطح المكتب؛ تحميل عند خمول المتصفح أو بعد تأخير أو نقرة.
- تكامل مع مدير الموافقة، ودليل إعداد وفحص يدوي للنظام ونص مقترح للخصوصية.
- إعدادات مستقلة لكل موقع في الشبكة وتنظيف اختياري عند الحذف.

## التثبيت

1. نزّل **hamgoo-live-chat-X.Y.Z.zip** من Releases. أرشيفات «Source code» الآلية ليست حزمة الإضافة الجاهزة للتثبيت.
2. في ووردبريس: إضافات ← أضف إضافة جديدة ← رفع إضافة؛ ثبّت ZIP وفعّل الإضافة.
3. فعّل همگو في لوحة همكاران، وأنشئ ودجت في إعدادات همگو ← الودجت، واضبط النطاقات المسموح بها.
4. افتح قائمة همگو في ووردبريس، وأدخل مفتاح `cw_` فقط، واقبل الاتصال بالخدمة وفعّل الدردشة واحفظ.
5. اضبط قواعد الصفحات والتحميل، واحذف السكربت القديم من القالب أو مدير الوسوم أو الإضافات الأخرى.
6. امسح ذاكرة التخزين المؤقت للموقع وCDN. أرسل رسالة من صفحة مسموحة وتحقق من وصولها ورد المشغّل.

الفحص اليدوي يجلب إعدادات الودجت صراحةً من متصفح المسؤول؛ نجاحه وحده لا يثبت السماح بالنطاق أو وصول الرسائل.

## قواعد العرض وWooCommerce

وضع كل الصفحات يسمح بالصفحات العامة المؤهلة. وضع الصفحات المختارة يتطلب تحقق شرط عرض واحد على الأقل؛ عدم اختيار شروط يخفي الدردشة في كل مكان. ترتبط شروط العرض بمنطق «أو». **أي استثناء يخفي الدردشة.**

المسارات نسبة إلى عنوان الصفحة الرئيسية لووردبريس، مسار في كل سطر. تُهمل معاملات query. `/contact` يطابق مع الشرطة المائلة الأخيرة أو بدونها. `/services/*` يطابق المسارات الفرعية، وللأصل أضف `/services` منفصلًا. `/*` يطابق الجميع.

عند تفعيل WooCommerce يمكن عرض الدردشة أو استثناؤها في المتجر والمنتج وأرشيف المنتجات والسلة والدفع والحساب. للصفحات المخصصة استخدم اختيار الصفحة أو المسار. بقية القواعد تعمل دون WooCommerce. لا يُدرج المحمّل في الإدارة أو AJAX أو REST أو cron أو feeds أو embeds أو المعاينات.

## التحميل والأداء

وضع الخمول ينتظر جاهزية الصفحة وخمول المتصفح. وضع التأخير ينتظر جاهزية الصفحة والمدة المحددة. وضع النقر يحمّل الخدمة بعد نقرة على الزر المحلي والموافقة عند اشتراطها. يحل الودجت الحقيقي محل الزر؛ فتح المحادثة تلقائيًا يعتمد على إعدادات همگو.

تُفحص الأجهزة في المتصفح لتوافق التخزين المؤقت؛ العرض حتى 767 بكسل يُعدّ جوالًا. الإضافة تضبط وقت التحميل والصفحات، ولا تغيّر بيانات SEO أو تضمن ترتيب البحث أو درجات الأداء.

## الموافقة والخدمات الخارجية

فعّل انتظار موافقة مدير ملفات الارتباط واربط مدير الموافقة في كل صفحة. الإضافة لا تعرض لافتة ملفات ارتباط ولا تحفظ الموافقة.

```js
// الموافقة قبل تنفيذ المحمّل:
window.HamgooLiveChatConsent = true;
// الموافقة بعد تنفيذه:
if (window.HamgooLiveChat) window.HamgooLiveChat.grantConsent();
// سحب الموافقة:
window.HamgooLiveChatConsent = false;
if (window.HamgooLiveChat) window.HamgooLiveChat.revokeConsent();
// أعد تحميل الصفحة دون موافقة لإيقاف ودجت بدأ العمل بالفعل.
// بديل بعد تشغيل المحمّل:
window.dispatchEvent(new CustomEvent('hamgoo:consent', {
  detail: { granted: true }
}));
```

الموافقة لا تتجاوز استثناءات الصفحات أو قيود الأجهزة. سحبها يمنع التحميل القادم؛ إيقاف كود خارجي يعمل بالفعل يتطلب إعادة تحميل الصفحة دون موافقة.

بعد شرط التحميل والموافقة، تُطلب `cp.hamkaran.cloud/widget/chat.js`. يستخدم الودجت `api.hamkaran.cloud` وأصول `cp.hamkaran.cloud` والمرفقات والصور في `storage.s1.hamkaran.cloud` وعميل `js.pusher.com` وعنوان websocket المحدد في الخدمة.

تكشف الطلبات عنوان IP وبيانات المتصفح المعتادة. قد تعالج الخدمة رابط الصفحة وعنوانها ومصدر الإحالة والمتصفح والجلسة وبيانات الزائر، مثل الاسم والهاتف والبريد والرسائل وحالة الكتابة والمرفقات والصوت. يُستخدم localStorage وsessionStorage، والتسجيل الصوتي يحتاج إذن الميكروفون. يحفظ ووردبريس إعدادات الإضافة فقط، لا المحادثات السحابية. فتح لوحة الإدارة لا يرسل طلبًا تلقائيًا للخدمة.

راجع [تفاصيل الخدمات الخارجية](../readme.txt) و[الخصوصية](https://hamkaran.cloud/privacy-policy/) و[اتفاقية الخدمة](https://hamkaran.cloud/%D8%AA%D9%88%D8%A7%D9%81%D9%82-%D9%86%D8%A7%D9%85%D9%87-%D8%A7%D9%85%D9%86%DB%8C%D8%AA%DB%8C/).

## اللغات والصور والحذف

الترجمات تخص لوحة الإضافة والزر المحلي؛ اضبط لغة الدردشة السحابية ولونها وموقعها وترحيبها وساعاتها في همگو. صور SVG المحلية مؤقتة؛ راجع [دليل الصور بالفارسية](artwork-fa.md) لبدائل WebP وأصول المتجر. يجب أن تكون لقطات المتجر من الإضافة الفعلية.

التعطيل يحتفظ بالإعدادات. الحذف يزيل إعدادات الموقع الحالي فقط إذا فُعّل التنظيف؛ تبقى المحادثات السحابية. لكل موقع في الشبكة مفتاح وإعدادات مستقلة.

## حل المشكلات

- لا تظهر الدردشة: تحقق من الخدمة والمفتاح وقبول الاتصال والنطاق والقواعد والاستثناءات والجهاز والموافقة.
- الإعدادات القديمة: امسح تخزين الموقع وCDN؛ يجب أن يستدعي القالب `wp_head()` و`wp_footer()`.
- تعارض التحسين: عند الحاجة استثنِ `hamgoo-loader` و`HamgooLiveChatLoader` و`cp.hamkaran.cloud/widget/chat.js` من الدمج أو التأخير الإضافي مع الحفاظ على الموافقة.
- فشل الفحص: قد تمنعه إعدادات المتصفح أو CORS؛ اختبر محادثة حقيقية أيضًا.
- تكرار الودجت: احذف التثبيت السابق.

لأسئلة الخدمة استخدم لوحة الدعم؛ لأخطاء الكود استخدم Issues. لا تنشر كلمات مرور أو رموزًا أو معلومات شخصية أو محادثات عملاء في البلاغات العامة.

## التطوير والإصدارات

يلزم PHP 7.4+ وComposer وPython 3.9+ وNode.js. من جذر المشروع:

```sh
composer install --no-interaction
composer lint
php tests/run.php
node --check assets/js/admin.js
node --check assets/js/loader.js
node tests/loader.test.js
python3 scripts/translations.py
git diff --exit-code -- languages
python3 scripts/verify.py
php scripts/preview.php
python3 scripts/package.py --tag v1.0.1
```

مصدر الترجمة `languages/translations.json`؛ تُنتج PO/MO/POT ويفشل التحقق عند نقص الترجمة. المعاينات الثابتة في `docs/*-preview.html`؛ البحث والاتصال الفعليان يحتاجان ووردبريس.

اختبار اختياري: `wp eval-file tests/wordpress-smoke.php`، **في تثبيت ووردبريس مؤقت منفصل فقط** مع الإضافة مفعلة. ينشئ محتوى وإعدادات مؤقتة؛ لا تشغّله على موقع حي أو موقع عميل.

وحّد Version وHAMGOO_VERSION في الملف الرئيسي مع Stable tag في readme.txt ووسم الإصدار. حدّث سجل التغييرات والاختبارات، ثم commit:

```sh
git tag v1.0.1
git push origin main
git push origin v1.0.1
```

يتحقق [CI](../.github/workflows/ci.yml) من الكود والترجمات والحزمة. ينشر [Release](../.github/workflows/release.yml) ZIP وSHA256SUMS بعد النجاح؛ يمكن تشغيله يدويًا لوسم مستقر موجود. إعادة التشغيل تحدّث ملفات الإصدار نفسه؛ لا تحرّك وسمًا منشورًا. نزّل الملفين معًا وشغّل `sha256sum --check SHA256SUMS`. تُستبعد الاختبارات وvendor والمستندات وworkflow من ZIP.

حساب الناشر ومعرّف WordPress.org قيد الانتظار. يبقى Contributors فارغًا حتى توفير الاسم الحقيقي؛ CI العادي يستثني هذا التحذير وحده عندما يكون فارغًا. نشر ووردبريس يتطلب الفحص الكامل. بعد الموافقة، اضبط الاسم والصور وأسرار SVN وفق [دليل النشر](release-fa.md). [workflow اليدوي](../.github/workflows/wordpress.yml) يتحقق من checksum وينشر إلى SVN. التحديثات عبر WordPress.org؛ لا يوجد محدّث GitHub خاص.
