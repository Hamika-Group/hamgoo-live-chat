# انتشار Hamgoo Live Chat

## وضعیت نسخه اول

افزونه در پوشه مستقل hamgoo-live-chat ساخته شده است. تصاویر محلی SVG موقت‌اند و WebP نهایی با همان نام‌ها جایگزینشان می‌شود. مخزن GitHub و حساب WordPress.org هنوز از طرف مالک ارائه نشده‌اند. نام کاربری Contributors در readme.txt عمداً خالی است؛ پیش از ارسال، نام کاربری واقعی حساب منتشرکننده را اضافه کنید.

## بررسی و ساخت بسته

از پوشه پروژه:

    composer install --no-interaction
    composer lint
    php tests/run.php
    node --check assets/js/admin.js
    node --check assets/js/loader.js
    node tests/loader.test.js
    python3 scripts/translations.py
    python3 scripts/verify.py
    python3 scripts/package.py --tag v1.0.0

خروجی dist/hamgoo-live-chat-1.0.0.zip مستقیماً از پیشخوان وردپرس قابل نصب است. فقط کد و فایل‌های لازم برای اجرا در آن قرار می‌گیرند؛ vendor، تست‌ها، workflowها، مستندات توسعه و تصاویر مارکت حذف می‌شوند.

ترجمه‌های انگلیسی متن پایه‌اند. منبع نگهداری ترجمه‌ها languages/translations.json است. اسکریپت translations.py فایل‌های PO و MO و POT را تولید می‌کند و اگر متن جدید بدون ترجمه مانده باشد، شکست می‌خورد. ترجمه‌ها مربوط به افزونه‌اند و تغییری در زبان ویجت ابری نمی‌دهند.

## بررسی دستی پیش از انتشار عمومی

در یک سایت آزمایشی با قالبی که wp_head و wp_footer دارد:

1. نصب تازه، بدون کلید: چت اجرا نشود؛ معرفی سرویس و لینک‌های سایت/مشاوره موجود باشند.
2. کلید صحیح، پذیرش سرویس و فعال‌سازی: پیام آزمایشی به همگو برسد و پاسخ دریافت شود.
3. کلید نامعتبر، دامنه غیرمجاز و سرویس غیرفعال: خطا یا عدم اتصال دقیق بررسی شود؛ موفقیت دریافت config را به معنی موفقیت ارسال پیام نگیرید.
4. برگه، نوشته، صفحه نوشته‌ها، خانه، آرشیو، جست‌وجو و ۴۰۴؛ استثنا بر همه قواعد مقدم باشد.
5. ووکامرس فعال و غیرفعال؛ محصول، دسته محصول، فروشگاه، سبد، تسویه‌حساب و حساب کاربری.
6. هر سه روش بارگذاری؛ موبایل و دسکتاپ؛ خروجی صفحات کش‌شده برای دستگاه‌ها یکسان بماند.
7. حالت رضایت؛ پیش از اجازه هیچ اتصال خارجی نباشد. پس‌گرفتن رضایت پیش از بارگذاری، درخواست را مسدود کند. برای توقف ویجت اجراشده، صفحه بدون اجازه دوباره بارگذاری شود.
8. پنج زبان پنل و جهت درست؛ ذخیره تنظیمات، جست‌وجوی محتوا و کار با کیبورد.
9. نصب قبلی اسکریپت: درج تکراری رخ ندهد؛ کد قدیمی باید توسط مدیر سایت حذف شود.
10. غیرفعال‌سازی و حذف؛ تنظیم پاک‌سازی فقط همان سایت را حذف کند. در وردپرس شبکه هر سایت مستقل تنظیم شود.

## GitHub

پس از دریافت URL مخزن، origin را برای همین پروژه تنظیم کنید و شاخه main را push کنید. این پروژه نباید داخل مخزن فرانت‌اند یا بک‌اند قرار بگیرد.

ci.yml بررسی PHP، استاندارد وردپرس، قواعد، بارگذار، ترجمه و Plugin Check رسمی را اجرا می‌کند. Plugin Check در محیط GitHub وردپرس واقعی راه‌اندازی می‌کند؛ اجراهای آن را از تست‌های سبک محلی جدا ببینید. تا نام کاربری واقعی Contributors ثبت نشود، بررسی مارکت هشدار می‌دهد و ریلیز خودکار متوقف می‌شود.

برای نسخه جدید، Version در فایل اصلی، ثابت HAMGOO_VERSION و Stable tag در readme.txt باید یکسان باشند. Changelog و متادیتای Tested up to را با تست واقعی همان نسخه هماهنگ کنید؛ سپس commit و push و تگ vX.Y.Z را ارسال کنید.

release.yml فقط پس از موفقیت بررسی‌ها، ZIP و SHA256SUMS را به GitHub Release اضافه می‌کند. نسخه آزمایشی در این workflow منتشر نمی‌شود. در صورت شکست، خروجی خطا را رفع و نسخه درست را منتشر کنید؛ تگ عمومی یک نسخه منتشرشده را جابه‌جا نکنید.

## WordPress.org

1. حساب منتشرکننده را بسازید؛ نام کاربری واقعی را در Contributors بنویسید.
2. تصاویر نهایی و اسکرین‌شات‌های واقعی را اضافه کنید. بخش Screenshots در readme.txt را با عکس‌های موجود هماهنگ کنید.
3. صحت صفحه توافق‌نامه و حریم خصوصی برای سرویس همگو و آدرس سرویس را بررسی کنید.
4. Plugin Check رسمی و آزمون عملی نصب و ارسال پیام را انجام دهید. نتیجه مربوط به نسخه واقعی را در Tested up to ثبت کنید.
5. ZIP را از https://wordpress.org/plugins/developers/add/ ارسال کنید و پاسخ‌های تیم بررسی را پیگیری کنید. پذیرفته‌شدن افزونه خودکار یا تضمینی نیست.
6. پس از پذیرش و تأیید شناسه hamgoo-live-chat، در GitHub environment با نام wordpress-org بسازید و secrets زیر را همان‌جا ذخیره کنید:

       WORDPRESS_SVN_USERNAME
       WORDPRESS_SVN_PASSWORD

   رمز SVN اختصاصی حساب را استفاده کنید. اگر وردپرس شناسه متفاوتی تخصیص داد، قبل از انتشار نام پوشه، text domain و workflow را هماهنگ کنید.

7. workflow وردپرس را با شماره نسخه پایدار موجود در GitHub اجرا کنید. همان ZIP بررسی‌شده دانلود و checksum آن بررسی می‌شود؛ trunk و tags نسخه در SVN و تصاویر موجود در assets منتشر می‌شوند.

به‌روزرسانی کاربران از مسیر استاندارد WordPress.org انجام می‌شود؛ افزونه updater خصوصی GitHub ندارد.

## استقرار راهنمای مشتریان همکاران

مقاله wordpress زیر help key موجود hamgoo.settings به منبع راهنمای مشتریان افزوده شده است. migration یا تغییر route لازم نیست.

پس از استقرار بک‌اند:

    cd laravel-backend
    php artisan help:seed
    php artisan help:audit --source-only

seed مقاله را در knowledge_items به‌روزرسانی یا ایجاد می‌کند و embedding به طور پیش‌فرض خاموش است.
